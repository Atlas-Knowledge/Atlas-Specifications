# ACCS-0001 — Atlas Common Concepts Specification

**Identifier:** ACCS-0001

**Version:** 1.0.0

**Status:** Draft

**Category:** Foundational Specification

**Repository:** Atlas-Specifications

---

# Abstract

The Atlas Common Concepts Specification (ACCS) defines the canonical concepts shared by all Atlas specifications.

It establishes the common vocabulary, identity model, object model, metadata model, lifecycle model, and reference model used consistently throughout the Atlas ecosystem.

All Atlas specifications MUST conform to ACCS.

---

# 1. Purpose

The purpose of ACCS is to provide a single authoritative definition for the common concepts used across all Atlas specifications.

This prevents duplication, inconsistency, and incompatible interpretations.

---

# 2. Scope

This specification defines:

- Identifier
- Canonical Identifier
- Namespace
- URI
- Object
- Object Type
- Property
- Metadata
- Version
- Status
- Lifecycle
- Reference
- Extension

This specification does not define domain-specific concepts such as Knowledge, Evidence, or Reasoning.

---

# 3. Common Concepts

## Object

An Object is the fundamental unit represented within Atlas.

Every Atlas Object MUST possess a unique identity and explicit type.

---

## Object Type

An Object Type defines the semantic classification of an Object.

Examples include:

- Entity
- Observation
- Evidence
- Claim
- Question
- Dataset

---

## Identifier

An Identifier uniquely distinguishes an Object within its namespace.

Identifiers MUST remain stable throughout the object's lifetime.

---

## Canonical Identifier

A Canonical Identifier is the permanent identifier assigned to an Atlas Object.

Canonical Identifiers MUST NOT change.

---

## Namespace

A Namespace defines the scope within which identifiers are unique.

Namespaces SHOULD remain stable.

---

## URI

A URI provides a globally addressable reference for an Atlas Object.

Implementations MAY use alternative identifier systems provided interoperability is preserved.

---

## Property

A Property represents a named characteristic of an Object.

Properties MAY contain scalar values, structured values, or references.

---

## Metadata

Metadata describes an Object without altering its semantic meaning.

Typical metadata includes:

- Labels
- Description
- Language
- Tags
- Creator
- Created Date
- Updated Date

---

## Version

Version identifies a specific revision of an Object.

Versions SHOULD follow Semantic Versioning whenever applicable.

---

## Status

Status represents the current lifecycle state of an Object.

---

## Reference

A Reference links one Atlas Object to another Atlas Object or to an external resource.

References SHOULD preserve traceability.

---

## Extension

Extensions allow additional properties or capabilities without violating mandatory requirements.

Extensions MUST remain compatible with this specification.

---

# 4. Common Object Model

Every Atlas Object MUST define:

- Identifier
- Object Type
- Version
- Status

Every Atlas Object SHOULD define:

- Metadata

Every Atlas Object MAY define:

- References
- Extensions

---

# 5. Lifecycle

Objects progress through the following lifecycle.

```
Draft

↓

Active

↓

Deprecated

↓

Archived
```

Implementations MAY define additional internal states provided compatibility is maintained.

---

# 6. Metadata Model

Metadata MAY include:

- Label
- Description
- Keywords
- Language
- Creator
- Contributors
- Creation Timestamp
- Last Updated Timestamp
- License

Metadata MUST NOT change the semantic meaning of an Object.

---

# 7. Reference Model

References MAY be:

- Internal
- External
- Canonical

Every reference SHOULD be resolvable whenever practical.

Broken references SHOULD be reported.

---

# 8. Versioning

Atlas Objects SHOULD follow Semantic Versioning.

Major versions indicate incompatible changes.

Minor versions indicate compatible additions.

Patch versions indicate corrections.

---

# 9. Conformance

An implementation claiming compliance with ACCS MUST:

- Implement stable identifiers.
- Support explicit object types.
- Preserve version history.
- Preserve lifecycle state.
- Distinguish metadata from semantic content.

---

# 10. Compatibility

Implementations SHOULD preserve backward compatibility whenever practical.

Breaking semantic changes MUST require a new major version.

---

# 11. Security Considerations

Implementations SHOULD protect:

- Identifier integrity
- Version history
- Metadata integrity
- Reference integrity

Security mechanisms are implementation-specific.

---

# 12. Normative Requirements

### ACCS-REQ-0001

Every Atlas Object MUST possess a globally unique Identifier.

### ACCS-REQ-0002

Every Atlas Object MUST define an explicit Object Type.

### ACCS-REQ-0003

Every Atlas Object MUST support versioning.

### ACCS-REQ-0004

Every Atlas Object MUST define a lifecycle state.

### ACCS-REQ-0005

Metadata MUST NOT modify the semantic meaning of an Object.

### ACCS-REQ-0006

Canonical Identifiers MUST remain immutable.

### ACCS-REQ-0007

References SHOULD preserve traceability.

### ACCS-REQ-0008

Extensions MUST remain compatible with mandatory requirements.
